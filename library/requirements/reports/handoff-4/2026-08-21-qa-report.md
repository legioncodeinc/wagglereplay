## 1. Summary

The shipped code (PRDs 001 through 010) is in materially better shape than the planning layer that now surrounds it: an independent re-run of the replay suite (63 of 63) and the real-ffmpeg credential canary confirms the moat contracts are genuinely present in code, and current build health shows zero code regressions (all 5 local test failures and all 378 lint errors are CRLF checkout artifacts or an unbuilt Studio, both environmental). The audit verdict is therefore: code green, plan red. Seven Critical findings block the path to production as currently written: the `waggle regen --check` flag is owned by three disagreeing sources and implemented nowhere; three backlog PRDs (013, 016, 017) instruct a builder to violate the locked ADR-019 CLI freeze; PRD-018's headline zero-terminal criterion (AC8) has three unowned prerequisites (project creation, GUI render and narrate triggers, extension delivery); extension delivery in turn depends on a Chrome Web Store review nobody has started; and release engineering (versioning, tags, release workflow, artifact checksums) does not exist at all for a project about to ship unsigned installers. None of these require hard engineering; nearly all require a documentation pass plus a batch of decisions only Mario can make.

## 3. Critical issues (must fix)

C1. `waggle regen --check` is contested three ways and implemented nowhere.
`packages/cli/src/commands/regen.ts:17-19` assigns the flag to prd-012; `library/requirements/backlog/prd-012-ci-regeneration/prd-012-ci-regeneration-index.md:7` names prd-011 as the blocker for check gates; `HANDOFF-3.md:182-183` says build prd-011 first so it defines the verdicts and exit codes; `EXECUTION_LEDGER.md:79` schedules both in the same wave with no ordering. A repo-wide grep confirms `--check` exists only in comments, docs, and PRD text. Whichever PRD dispatches first will duplicate or stall. Resolve ownership in writing before any Wave dispatch of 011 or 012, and note that ADR-019 names only prd-012 for the carve-out, so the ruling should also touch ADR-019's interaction note.

C2. PRD-013 AC1 (`waggle narrate --audio file.mp3`) violates ADR-019's CLI freeze.
`prd-013-audio-upload-alignment-index.md:20` adds a new flag to an existing command; ADR-019 (`ADR-019-cli-frozen-gui-primary.md:11`) forbids new user-facing commands or flags beyond what prd-001 and prd-012 scope, and prd-006 lists uploaded-audio alignment as an explicit non-goal. PRD-013 predates ADR-019 by one day and never cites it. Either reroute audio upload through Studio, or amend ADR-019 with an explicit carve-out, before build.

C3. PRD-016 AC2 ("yolo flag that is loud in output") and PRD-017 AC4 ("confirm flag for non-interactive runs") are CLI-flag-shaped ACs that conflict with ADR-019, and neither PRD cites ADR-019 or ADR-017.
Evidence: `prd-016-audio-only-generation-index.md:21` and `:7`; `prd-017-avatar-pip-plugin-index.md:25` and `:7`. Rewrite as Studio UI affordances or env-var guardrails (the shipped precedent is `WAGGLE_ALLOW_UNLICENSED_AUDIO` in `packages/narrate/src/guardrails/shareable-audio.ts`), or amend ADR-019.

C4. PRD-018 module AC8 (zero-terminal install-to-render) cannot pass as written: three prerequisites have no owner in sub-PRDs a through g.
(1) Project creation and selection: `apps/studio/src/lib/server/project-context.ts:40-57` hard-requires `WAGGLE_PROJECT_DIR` and its error text tells the user to run `waggle init`, which is a terminal. (2) GUI narrate and render triggers: `apps/studio/src/routes` has no render, narrate, or regen route, and prd-018f explicitly excludes Studio-side orchestration changes. (3) Extension delivery with a fixed packed id: `apps/extension/manifest.json` has no `key` field, prd-018b's origin allowlist depends on one, and no sub-PRD packs or installs the extension. One or two new sub-PRDs are required before AC8 is achievable.

C5. Extension delivery depends on a Chrome Web Store review that has not been started, and off-store install is not a real fallback on Windows or macOS.
The manifest's permission profile (tabCapture, webRequest, host permissions on all origins) draws manual review requiring a hosted privacy policy URL, a single-purpose declaration, and per-permission justifications; none exist in the repository and no PRD, ADR, or ledger row owns producing them. This is a third-party latency sitting on the critical path of AC8. Start the submission ahead of prd-018g.

C6. Release engineering does not exist.
Zero git tags, zero GitHub releases, every workspace package frozen at 0.1.0 and private with no license field, `CHANGELOG.md` has only an Unreleased section, and `.github/workflows/` contains only ci.yml and codeql.yml. prd-018g would ship installers with no version, no rollback target, and no release notes. Decide the versioning unit, add a tag-triggered release workflow, and cut a first tag before any installer is published.

C7. An unsigned installer with no published checksum offers the user no integrity signal.
ADR-020 accepts unsigned builds and prd-018g covers the install copy, but nothing publishes a SHA-256 per artifact with a verification command, and no AC keeps an auto-updater out or documents the manual update path. The install copy currently trains users to dismiss the only warning they get. Add checksum publication to the release workflow and an updater-absence AC to prd-018g.
